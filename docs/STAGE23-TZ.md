## 0. Как работать (конвенции владельца — ОБЯЗАТЕЛЬНЫ)

- Этапы с отчётами, БЕЗ остановок между ними; после каждого этапа — локальный `git commit`
  с тегом `[StageNN.k]` в сообщении (НЕ пушить). PS 5.1: многострочные коммиты только через
  `git commit -F <файл>` (here-string с LF ломается).
- После каждого этапа: `./gradlew build` зелёный (тесты обязательны). ArchitectureRuleTest
  запрещает RenderSystem/BufferBuilder/… вне `com.club.ui.backend` — низкоуровневое кладём
  в `com.club.hud` (ванильный слой, прецедент PixelIcons).
- Ответы владельцу — русский; UI-лейблы — English. Владелец ревьюит попиксельно; вкусовые
  решения — только через варианты/доски (HTML-мокап или Artifact), не решать за него.
- Дизайн-законы: плоско, без glow/градиентов на тексте; цвета из `Tokens` (тема ClubDark);
  цифры не красим состоянием (identity-тинт 25–30% разрешён); капсулы/колодцы вместо линий.
- Технические ловушки: текст/глифы НЕ фейдятся pushOpacity → только `Color.scaleAlpha`;
  клип прямоугольный; `Mouse.lockCursor()` в 1.21.1 вызывает `setScreen(null)` (см. память
  mc-lockcursor-trap — курсор прятать сырым GLFW-грабом + MouseAccessor, зеркаля ваниль:
  cursorLocked + x/y в центр + обнулить дельты); фокус-кольца только с клавиатуры
  (`isFocusVisible`); иконки: `./gradlew genIconAtlas genIconPreviews`, превью
  `build/icon-previews/board.png`; HUD-иконки = дуотон ванильных текстур (`com.club.hud.PixelIcons`),
  SDF-глифы — фоллбек.
- Моушн меню отполирован владельцем до констант — НЕ трогать значения: `EXIT_DUR 0.30 /
  ENTER_DUR 0.28 / MOVE_DUR 0.34 / MOVE_DELAY 0.07 / ENTER_DELAY 0.11 / CAT_STAGGER 0.042 /
  EXIT_STAGGER 0.105 / CAT_DRIFT 6`; каскад выходов — С ХВОСТА; категории — fade+подъём
  (без scale!); поиск — scale 0.97↔1. Композиция окна Stage 22 (колодцы #111927/#131A28,
  гало квадратичное {9,8,7,6,5,4,3,3,2,2,2,1,1,1}×2px) — утверждена, не менять.
- Доки живут амендментами: после этапов дополняй `HUD-LANGUAGE.md` / `UI-V2-MENU.md` /
  `ANIMATIONS.md` (баннер-амендмент, не переписывание), и обновляй память ассистента.

## Порядок этапов (утверждён владельцем)

### Stage 23 — Target HUD: данные до уровня визуала
Файлы: `com/club/hud/TargetHud.java`, `com/club/ui/hud/TargetElement.java`, `HudEditorScreen`.
1. **Стены:** `raycastTarget` (TargetHud:28-31) использует только `ProjectileUtil.raycast` —
   цели видны СКВОЗЬ стены. Добавить `world.raycast` (блоки) и клампить дистанцию луча по
   первому блоку (семантика ванильного прицела). Плашка не должна показывать сущностей за стеной.
2. **Идентичность цели по entity ID, не по имени:** tweenName/popName (TargetElement:76,104)
   сравнивают строки — зомби→зомби не снапит HP-твин и не играет acquire-pop. Трекать
   `entity.getId()`; снап твина и поп — при смене ID.
3. **Один рейкаст на кадр + честный tickDelta:** сейчас 2 рейкаста/кадр (hasContent + resolve)
   с tickDelta=1f. Кэшировать результат на кадр; передавать реальный partial tick.
4. **Grace-окно:** прицел соскользнул на 1 кадр → чип мерцает. Держать цель ~200мс после
   потери (потом обычный fade-out канваса).
5. **Предикат:** добавить `Entity.canHit()` (EntityPredicates.CAN_HIT) — армостенды и
   невидимые не цели.
6. **Дистанция:** код клампит 3..64 (TargetHud:24), UI-слайдер 3..32 (HudEditorScreen:114) —
   привести к 3..32 везде.
Приёмка: за стеной цели нет; переключение между двумя мобами = мгновенный снап + поп;
чип не мерцает при страйфе; армостенд не цель.

### Stage 24 — Анимации рук (флагман): починить и синхронизировать доки
Файлы: `com/club/mixin/MixinHeldItemRenderer.java`, `modules/animations/*`, `docs/ANIMATIONS.md`.
1. **Оффхенд-баг (ГЛАВНОЕ):** club$captureSwing (MixinHeldItemRenderer:57-63) зануляет свинг
   ОБЕИХ рук, а re-apply (:86-96) только для MAIN_HAND и не проверяет, какая рука реально
   махнула (ваниль гейтит по `player.preferredHand`). Итог: свинг оффхенда съедается, и его
   прогресс играет атаку на ГЛАВНОЙ руке. Чинить: перехват/возврат строго per-hand по
   preferredHand.
2. **SPIN:** `sample` = `arm * -360f * s` (AnimationType:61-64) — Amplitude игнорируется
   (мёртвый слайдер в меню) и нет easing-языка остальных типов. Применить amp и кривую.
3. **Доки:** ANIMATIONS.md — амендмент-баннер (по образцу DESIGN/HUDS): убрать ссылку на
   удалённый `gui/ClubScreen` (:22 → меню = `ui/menu/MenuContent`), исправить единицы
   трансляции — БЛОКИ, не 1/16 (:17, :57; также javadoc Pose.java:3).
4. Мелочь: `new Pose()` аллоцируется каждый кадр при out-param API (:88) — реюзить;
   VANILLA.sample мёртв — пометить/упростить.
Приёмка: постановка блока оффхендом анимируется корректно на своей руке при любом типе
анимации; Amplitude влияет на SPIN; доки соответствуют коду.

### Stage 26 — LEGACY: честная деградация
Файлы: `ui/backend/*`, `ui/IconGlyph.java:84`, `ui/menu/ClubMenuScreen.java`,
`ui/hud/EffectsElement.java`, `ui/hud/ArmorElement.java`, `hud/PixelIcons.java`.

LEGACY = парашют, красить не надо, но он обязан быть ЧЕСТНЫМ и читаемым.
1. **Громкое предупреждение:** если backend == LEGACY — заметная плашка в меню/HUD
   («UI fallback mode — check resource packs / report») + WARN в лог (один раз).
2. **Буквенный фоллбек иконок:** там, где глиф/дуотон не нарисовался: карточки меню — инициал
   модуля в чипе (сейчас пустые квадраты, :899-900), ряды Effects — инициал эффекта (сейчас
   «II · 1:24» БЕЗ идентичности — имена удалены в Stage 14), Armor — инициал слота; в шапке
   не резервировать ширину лого, если глиф пропущен (:535-539); футер-чип аналогично.
3. **Гало гейтить** на LEGACY (pushOpacity no-op → 14 сплошных чёрных рамок).
4. **Стейл-джавадоки** про LEGACY: EffectsElement:30, ArmorElement:28-29 — описать реальность
