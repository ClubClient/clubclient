## 1. Что выяснила разведка (и почему план именно такой)

**Item Scroll.** Механика оригинала (masa's Item Scroller) разобрана по жестам, а протокол — по байткоду
1.21.1: всё делается одним и тем же вызовом `interactionManager.clickSlot(...)`, и **N кликов = N пакетов**,
батч-пакета не существует. Отсюда единственный настоящий риск: **массовое перекладывание — это очередь
пакетов**, а NoCheatPlus по умолчанию режет на `4 клика/тик` и `15 кликов/сек`, причём действием `cancel` —
игрок не видит кика, он видит, как предметы прыгают обратно, и винит в этом Club. Безопасный темп (15/с) даёт
**4.5 секунды на большой сундук**, тогда как оригинал делает это мгновенно. Это не техническая проблема, а
продуктовая — см. решение №1.

**Оптимизация.** Честная отправная точка: **сегодня Club не оптимизирует ничего и стоит 0.45 мс на кадр.**
Прежде чем говорить «с модом игра идёт лучше», это надо сначала отдать, а потом обогнать. Sodium уже владеет
рендером мира и с 0.6 сам отсекает сущности по секциям. Свободными остались ровно четыре вещи: **частицы**
(ваниль не отсекает их вообще — проверено), **block-entity по фрустуму**, **троттлинг в фоне** (в 1.21.1 его
нет) и **наша собственная стоимость**. Всё остальное — либо чужая работа, либо ложь.

**Настройки.** Претензия «вкладки туда-сюда ездят» расшифровывается точно: меню анимирует **саму раскладку** —
пилюля рельсы едет, сетка карточек **пересобирается и заново проигрывает появление** на каждом переключении
категории, поповер «вырастает». Всё это — реакция на простую **навигацию**, а не на действие игрока. А
«однообразно и дёшево» — это то, что все 12 модулей выглядят одинаковой коробкой 58px, и все поповеры —
одинаковым листом 236px.

## 2. Решения, которые нужны ОТ ВЛАДЕЛЬЦА до старта

### ~~Решение 1~~ — ЗАКРЫТО владельцем

Item Scroll **включён по умолчанию, мгновенный, без предупреждений и гейтов** — как самый популярный мод в этой нише.
Режим `Paced` остаётся опцией в настройках на случай серверов, которые откатывают предметы. Тема закрыта.

### Решение 2 — постоянная панель настроек вместо поповера (блокирует чат C)

Разведка предлагает заменить ПКМ-поповер на **постоянную панель справа** (master-detail): тогда ничему не надо
«вырастать» и «схлопываться», и половина твоей претензии исчезает структурно. **Но это разворот твоего же
решения Stage 6** («постоянной панели настроек нет — настройки в ПКМ-поповере»), зафиксированного в
`docs/UI-V2-MENU.md`. Нужно твоё «да» или «нет».

- **Да** → чат C делает master-detail: слева категории, в центре карточки, справа живая панель настроек.
- **Нет** → чат C оставляет поповер, но убирает всю анимацию раскладки и делает карточки разными по смыслу
  (живые показания: у Zoom — кратность, у HUD — миниатюра, у Hands — кисть).

### Решение 3 — что режем в Item Scroll (рекомендация: режем)

Разведка предлагает **отложить**: торговлю с жителями, память рецептов крафта и креативный инвентарь. Это
самые «прибитые сбоку» части оригинала и самая большая античит-поверхность. На карточке модуля будет честная
строка «Creative inventory: not handled» — механизм `MenuContent.notice()` уже есть (Stage 62).

### Решение 4 — клавиша `C` (висит с прошлого раза)

Зум по умолчанию на `C`, там же ванильный `Save Toolbar Activator`. Оставляем (рекомендую) или уводим?

## 3. Разделение файлов: кто чем владеет

Три чата работают **одновременно**, поэтому границы жёсткие. Файл имеет **ровно одного владельца**. Если тебе
нужен чужой файл — ты не трогаешь его, а используешь **шов** (§4).

| Чат | Ветка | Владеет целиком |
|---|---|---|
| **A · Item Scroll** | `feat/itemscroll` | `com/club/modules/itemscroll/**`, `com/club/mixin/MixinHandledScreen*.java`, `docs/ITEMSCROLL.md` |
| **B · Оптимизация** | `feat/perf` | `com/club/modules/perf/**`, `com/club/mixin/MixinWorldRendererCull.java`, `MixinBlockEntityRenderDispatcher.java`, `MixinParticleManager.java`, `MixinMinecraftClientFps.java`, `com/club/harness/ClubBench.java`, `docs/PERF.md` |
| **C · Настройки** | `feat/menu` | `com/club/ui/menu/**`, `com/club/ui/component/**`, `docs/UI-V2-MENU.md`, `docs/DESIGN.md` |

**Ничей (общий) — трогать ТОЛЬКО через швы §4:**
`ClubConfig.java` · `MenuContent.java` (владелец C, но A и B добавляют по одной строке) · `ClubClient.java` ·
`club.mixins.json` · `ClubHarness.java`

**Никто не трогает:** `com/club/ui/hud/**`, `com/club/hud/**`, `com/club/modules/{zoom,freelook,fullbright,
togglesprint,hands,animations,screenstretch,binds}/**`, `ClubPromo.java`, `tools/promo/**`.

## 4. Швы: как добавить своё в общий файл, не подравшись

В каждый общий файл **первым коммитом** ставятся якоря-комментарии (это делаю я, до старта чатов). Правило
одно: **добавлять строку строго под своим якорем, ничего вокруг не переформатировать.** Тогда git сливает три
ветки без конфликтов, потому что три чата пишут в три разных места файла.

```java
// ClubConfig.java
// [SEAM:config] модульные секции — каждая новая одной строкой, под своим якорем
public ItemScroll itemScroll = new ItemScroll();      // ← чат A
public Perf perf = new Perf();                        // ← чат B
```

```java
// MenuContent.java, внутри build()
new Category("Misc", IconGlyph.MISC, List.of(
    hudEditor(openHudEditor),
    // [SEAM:cards] карточки новых модулей — по одной строке
    com.club.modules.itemscroll.ItemScrollMenu.card(),   // ← чат A
    com.club.modules.perf.PerfMenu.card(),               // ← чат B
    ...
```

Аналогично: `ClubClient.onInitializeClient` → `// [SEAM:init]`; `club.mixins.json` → массив `client`
(добавлять в конец); `ClubHarness.build()` → `// [SEAM:checks]`.

**Каждый чат обязан:** свою логику держать в своём пакете; в общий файл добавлять **только вызов**. Никакой
бизнес-логики в `MenuContent` или `ClubClient`.

## 5. Порядок слияния

1. **C (меню)** — первым, потому что он меняет язык карточек и поповеров, а A строит на нём свой экран
   привязок жестов. Пока C не влит, A использует существующие дескрипторы (`Setting`), они не исчезнут.
2. **A (item scroll)** — вторым.
3. **B (оптимизация)** — третьим (у него самый маленький UI-след, ему проще всех пере-базироваться).

Перед слиянием каждая ветка: `git rebase main` → полный прогон харнесса → **56/57 минимум, без новых красных**.

## 6. Общие правила для всех трёх (нарушать нельзя)

- **Проверять в игре, а не «должно работать».** Харнесс (`CLUB_HARNESS=1`) + скриншоты. Владелец смотрит
  попиксельно.
- **Каждый этап — локальный коммит** (без push, если не просили). Сообщение объясняет *почему*, а не *что*.
- **Комментарии в коде — на английском**, объясняют причину, а не пересказывают строку.
- **Строки интерфейса — только английский.**
- **Дизайн заморожен:** плоский, без glow/glass, без градиента на тексте (единственное исключение —
  подчёркивание активной вкладки). Палитра — `docs/DESIGN.md`.
- **Владельцу отвечать по-русски**, по существу, без воды.
- Ничего не обещать в описании мода, чего не измерил.

## 7. Критерий готовности всего цикла

- Харнесс зелёный (кроме известного порога 0.8 мс, который падает и на чистом HEAD — см. Stage 63).
- Item Scroll: ни одного кика на сервере с NoCheatPlus в ручной проверке; конфликтующие жесты невозможно
  назначить.
- Оптимизация: **измеренная** дельта FPS в фиксированной сцене, ON vs OFF, в одной сессии. Если дельта в
  пределах шума — так и написать, а не выдумывать.
- Настройки: владелец говорит «ничего не ездит» и «не выглядит дёшево».
