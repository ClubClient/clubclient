> red-концепта = референс стиля, НЕ утверждённые цвета/контент). Пояснения — русский,
> идентификаторы/код — English. Контрольные точки владельца: после 11.2 (техника), 11.3 (стиль

## 0. Цель

Карточки модулей сейчас — только имя, читаются пусто. Стадия добавляет: **иконку** каждому модулю,
**ghost-подложку** (та же иконка, крупно, еле заметно), **цвет категории** как идентичность,
**полосу состояния** вместо любых надписей, заменяет процедурные иконки rail/поиска на новый набор
и даёт слову CLUB настоящий **логотип**.

## 1. Палитра категорий — «Вариант A» (УТВЕРЖДЕНА)

Токен `Tokens.categories()` (`theme/CategoryAccents.java`), значения в `ClubDark`:

| Категория | Hex | Ассоциация |
|---|---|---|
| Combat | `#C9808A` | приглушённый красный — атака/урон |
| Visuals | `#9E8BD9` | приглушённый фиолетовый — рендер; преемственность с violet-кромкой вкл-карточки |
| Player | `#7FBFA6` | холодная бирюза-зелень — тело/сам игрок |
| Misc | `#8C9BB5` | серо-стальной — инструменты, самая тихая |

Все выровнены по светлоте/приглушённости (калибровка — steel-blue `#86A6CC` HP-бара).

**Правила цвета (утверждены):**
- **Категорийный цвет = только идентичность:** чип иконки, полоса состояния, ghost, индикатор rail.
- **Бренд `#7CABFF` = только интерактив:** поиск, слайдеры, кнопки, поповер — одинаков во всех категориях.
- **Текст никогда не красится** категорийным цветом (правило v2.5 действует).
- Off-канал (серые состояния) — из существующих токенов (textDesc/textFaint/border), решается в 11.4;
  новых серых hex не вводить без необходимости.

## 2. Карточка модуля — анатомия и состояния (УТВЕРЖДЕНО)

```
┌────────────────────────────────┐
│ ┌────┐                    ░░░░ │   чип 30×30 (radius 8, категорийный цвет @ ~12% фон,
│ │icon│  Module Name      ░ghost│   иконка ~17px категорийным цветом)
│ └────┘                    ░░░░ │   ghost: та же иконка 3–4×, alpha ~5–8%, у правого края,
│  ▬▬▬ ← полоса                  │   клипится границей карточки
└────────────────────────────────┘
```

- **Полоса состояния:** короткий штрих (~16×3), **геометрически по центру под чипом** (на мокапе
  была кривая — у нас точно по центру). Живёт ВСЕГДА; меняется только цвет: серый = выкл,
  категорийный = вкл; цвет едет существующим `Transition` (серый ↔ цвет) — ничего не прыгает.
- **Полоса — подтверждение, не единственный сигнал:** выкл = серая иконка + приглушённое имя +
  бледный ghost; вкл = цветная иконка + яркое имя + заметнее ghost.
- **Никакого текста «Enabled/Disabled»** на карточках.
- LMB = toggle, RMB = поповер — поведение Stage 6 не меняется.

## 3. Иконки — стиль и формат исходников

- Сетка **24×24**, штрих **2px**, круглые концы и стыки (`stroke-linecap/linejoin: round`),
  монохром (один цвет — красится в рантайме).
- Исходники: `tools/icons/src/<name>.svg`. Перед сдачей штрихи **переводятся в заливки**
  (outline stroke) и объединяются в **один составной path** — требование msdfgen.
- Диагонали разрешены и приветствуются: ограничение R8 (процедурные иконки без диагоналей)
  на MSDF-путь **не распространяется** — оно остаётся только историей.
- Набор (первая волна → полный):
  - **Модули (~8–10):** Animations, Screen Stretch, No Hurt Cam, No Fire Overlay, No Bobbing,
    Hands, HUD Editor, Hide Vanilla Effects (+ будущие).
  - **Категории (4):** Combat, Visuals, Player, Misc — заменяют процедурный `Icon` в rail.
  - **Служебные:** search (заменяет `Icon.SEARCH`), logo-mark CLUB.
- Судьба `Icon` (процедурного): после миграции rail/поиска остаётся только как чертёжный
  инструмент, если где-то ещё нужен; вероятно удаляется в конце 11.5 (решим по факту).

## 4. Логотип CLUB

Сейчас: акцентный квадрат 8×8 + слово «CLUB» (шапка меню, watermark редактора). Делаем настоящий

## 5. Конвейер (11.2)

```
tools/icons/src/*.svg
   └─ gradle task genIconAtlas:
        1) скачивает pinned msdfgen (exe, тот же автор, что msdf-atlas-gen; версия+checksum)
        2) msdfgen -svg на каждую иконку → MSDF-тайл (px-range как у шрифтового атласа)
        3) собственный packer (Java, в buildSrc/задаче) собирает тайлы в один PNG-атлас
           + JSON-метрики в схеме, совместимой с MsdfMetrics (иконка = «глиф» в PUA-кодпоинтах)
   → src/main/resources/assets/club/ui/icon/msdf/icons.{png,json}
```

Рантайм: атлас грузится как ещё один `MsdfAtlas` (заложенный в `FontRegistry` icon-seam),
рисуется **существующим** шейдером `ui_msdf_text` (иконка = глиф: та же резкость на любом размере,
тонировка цветом стиля, `WeightBias=0`). Ghost = тот же глиф крупным размером с малой альфой под
клипом карточки. Никакого нового рендер-кода, кроме тонкого `IconGlyph`-API поверх.

**Приёмка 11.2:** тестовая иконка резкая в 17px (чип) и в 64px+ (ghost); LEGACY-фолбэк не падает
(иконки в legacy-режиме допустимо не рисовать / рисовать заглушкой — решить при реализации).

## 7. Риски / открытое

- **R6 (rect-only rounded clip):** ghost у скруглённого угла карточки может резаться квадратно —
  на альфе 5–8% ожидаемо незаметно; проверяем глазами в 11.4, лечим только если видно.
- **msdfgen и multi-path SVG:** страховка — правило «один составной path на иконку» (см. §3).
- **Off-канал серых** — выбрать из существующих токенов в 11.4.
- Категорийный цвет в **поповере** сознательно НЕ используется (интерактив = бренд); если после
  живой проверки захочется лёгкой категорийной подкраски заголовка поповера — отдельное решение владельца.
