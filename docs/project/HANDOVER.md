## 1. Что это за проект
**Club** — клиентский utility-мод для Minecraft на **Fabric 1.21.1** (Yarn, Java 21), пакет `com.club`. Премиальный
first-person клиент: кастомные анимации рук, screen-stretch, визуальные твики, HUD, меню на Right Shift. Существующая
часть (старый UI, модули, миксины) описана в `docs/ARCHITECTURE.md` и работает.

Главная текущая инициатива — **миграция всего UI на новый рендер-стек** (`com.club.ui`), потому что старый стек уперся
в потолок качества.

## 2. Почему вообще понадобился новый рендер
Старый UI рисуется так: фигуры — `DrawContext.fill` осепараллельными квадами с покадровым CPU-расчётом AA; текст —
ванильный bitmap-`TextRenderer`. Симптомы: пиксельный текст на зуме/4K, свечения «набором квадратов», грязные
(полосящие) градиенты, ступенчатые скругления, развал интерфейса при приближении. Это **архитектурный потолок** —
косметикой не лечится. Поэтому решено заменить сам стек.

Новый стек: **MSDF-текст** (multi-channel signed distance field — резкость при любом масштабе, острые углы букв) +
**аналитический SDF для фигур** (`sdRoundBox` в шейдере — resolution-independent скругления/бордеры/glow/градиенты, AA
через `fwidth`). Всё на GPU, без CPU-эффектов. Подробное обоснование и отвергнутые альтернативы (NanoVG, одноканальный
SDF, JCEF) — в [DECISIONS.md](DECISIONS.md).

## 3. Почему архитектура именно такая
Цель — **перестать переписывать UI заново** и построить систему на годы. Отсюда ключевые решения:
- **Контракты отдельно от реализации.** `UiRenderer`/`UiText`/`UiContext` — чистые (MC-free) интерфейсы; их реализуют
  бэкенды. Компоненты будущих этапов кодируются против контрактов и не знают про GL.
- **Backend-only rendering (жёсткое правило).** Весь низкоуровневый GL (`RenderSystem`/`BufferBuilder`/`GlUniform`/
  `DrawContext.fill`/...) — ТОЛЬКО в `com.club.ui.backend.*`. Всё остальное рисует через `Ui.renderer()`/`Ui.text()`.
  Это машинно проверяет `ArchitectureRuleTest`. Цель — чтобы кодовая база не начала обходить новый стек напрямую.
- **Фасад `Ui`** выбирает активный бэкенд и **авто-падает на LEGACY**, если MODERN недоступен (шейдер/атлас не
  загрузились) — без краша. `LegacyBackend`/`LegacyText` существуют только как fallback.
- **Слоистый текст:** Atlas (текстура) → Metrics (метрики) → Layout (раскладка, чистая, codepoint-aware) → Renderer
  (GPU). Layout отделён через `GlyphSource`/`GlyphSink` (out-param, без аллокаций), поэтому позже можно добавить
  bidi/RTL/emoji/fallback-fonts, не переписывая рендер.
- **Alloc-free hot path + заложенные batching-seams** (текст — самый дорогой элемент UI).
Полная карта слоёв и правил — [ARCHITECTURE.md](ARCHITECTURE.md). Точные сигнатуры контрактов — `docs/UI-V2.md`.

## 4. Что уже завершено
**Stage 1 (рендер-фундамент) — готов и в `main`** (merge `ce27dab`, `gradlew build` зелёный):
контракты `UiRenderer`/`UiText`/`UiContext`/`Ui`; `ModernBackend` (SDF) + `ModernText` (MSDF) + `LegacyBackend`/
`LegacyText` (fallback); core-шейдеры `ui_sdf_shape`/`ui_msdf_text`; замороженные MSDF-атласы Inter (Latin+Cyrillic) +
Gradle-задача `genMsdfAtlas`; JUnit-тесты + arch-guard. Рантайм проверен скриншотами: шейдеры компилируются, текст
(латиница и кириллица) резкий и на 1×, и на 500% зуме; все SDF-примитивы + эффекты + клиппинг работают; при «пропаже»
атласа весь UI graceful-падает на LEGACY без краша. После финального adversarial-ревью (4 измерения) важные находки
исправлены. PoC-слой и временные demo/bootstrap **удалены** — база чистая; фундамент сейчас **library-only** (без
in-client точки входа — её добавит Stage 2/3, вызвав `Ui.init()`).

## 5. Принципы, которые нельзя нарушать
- **Backend-only** — никакого низкоуровневого рендера/`DrawContext`/`ClubFont`/`RenderHelper` вне `backend/`.
- **Не трогать существующие** `gui/*`, `hud/*`, `Theme`, `ClubFont`, `RenderHelper` — **до Stage 5**.
- **Не менять сигнатуры контрактов** Stage 1 без approve.
- **Никаких CPU-эффектов** и **никаких аллокаций в render-хотпате** из своего кода.
- **Никаких временных решений** в постоянном коде; **сначала архитектура, потом реализация**; **не жертвовать
  качеством ради скорости**; **один Stage за раз**.
- **Не принимать архитектурные решения самостоятельно — всегда approve пользователя.**
Полный свод правил и рабочий процесс — [AI_CONTEXT.md](AI_CONTEXT.md).
