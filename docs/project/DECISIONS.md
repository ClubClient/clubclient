# DECISIONS — журнал архитектурных решений

> Почему сделано так, а не иначе. Каждое решение: суть · причина · отвергнутые альтернативы. Не менять задним числом;
> новое решение — новая запись. Зафиксированные решения Stage 1 также в `docs/UI-V2.md` §10.

**D-01 · Текст через MSDF.** Резкость при любом масштабе/зуме/4K и сохранение острых углов глифов на мелком кегле.
Отвергнуто: bitmap-атлас (=старый стек, разваливается на зуме); одноканальный SDF (мылит углы на 12–13px); NanoVG
(bitmap-текст + рантайм-нативы). Прецедент — мод Caxton.

**D-02 · Фигуры через аналитический SDF (`sdRoundBox`).** Resolution-independent скругления/бордеры/glow/градиенты на
GPU, AA через `fwidth`. Отвергнуто: CPU-AA (per-pixel coverage квадами) — не масштабируется, дорогой, «блочный».

**D-03 · Backend-only rendering.** Весь низкоуровневый GL инкапсулирован в `com.club.ui.backend.*`; всё остальное —
через `Ui.renderer()`/`Ui.text()`. Причина: чтобы кодовая база не начала обходить новый стек напрямую (главная причина
прошлых «36 переписываний»). Enforced `ArchitectureRuleTest`.

**D-04 · Никакого `DrawContext.fill`/bitmap-текста как основного.** Это и есть потолок старого стека. Допустимы только
внутри `LegacyBackend`/`LegacyText` как временный fallback.

**D-05 · Контракты отдельно от реализации.** `UiRenderer`/`UiText`/`UiContext` — MC-free интерфейсы; бэкенды
реализуют их. Позволяет менять бэкенд (Modern↔Legacy, будущий батчер) без переписывания компонентов.

**D-06 · Сначала фундамент, потом компоненты/стиль/функционал.** Контракты зафиксированы и проверены до кода. Цель —
строить систему на стабильной базе, а не переписывать UI заново.

**D-07 · Stage 1 — library-only (без in-client входа).** Чистая база без временных bootstrap’ов. Точку входа
(`Ui.init()` — регистрация шейдеров) добавит Stage 2/3 при интеграции ClickGUI. Existing-клиент не трогаем до Stage 5.

**D-08 · PoC удалён после Stage 1.** PoC (`com.club.poc`) доказал реализуемость MSDF+SDF и был вытеснен `com.club.ui`.
Оставлять = наследие/мусор. Доказательства сохранены в `docs/` (UI-V2, POC-RENDER-STACK) и истории git.

**D-09 · `Ui` — фасад.** Единая точка: выбор активного бэкенда + авто-fallback на LEGACY при недоступности MODERN
(`modernAvailable()`), `beginFrame()`, `init()`. Компоненты развязаны от выбора бэкенда.

**D-10 · MSDF-атлас генерится офлайн (`genMsdfAtlas`), рантайм-нативов нет.** Поставляем PNG+JSON, грузим чистым
Java/GLSL. Отвергнуто: рантайм-генерация (как Caxton через Rust-либу) — лишняя натив-зависимость под каждую ОС.

**D-11 · Полный charset заморожен один раз** (Latin+Latin-1+Cyrillic+symbols, `-size 40 -pxrange 6`). Чтобы не
возвращаться к атласам на поздних этапах и не ломать совместимость компонентов.

**D-12 · Слоистый текст (Atlas/Metrics/Layout/Renderer) + `GlyphSource` out-param.** Layout (раскладка) отделён от
рендера через `GlyphSink`/`GlyphSource`; можно заменить только Layout (bidi/RTL/emoji/fallback-fonts) без переписывания
рендера. Out-param (mutable holder) — чтобы резолв глифа не аллоцировал на хотпате.

**D-13 · Alloc-free render hot path + заложенные batching-seams.** Текст — самый дорогой элемент UI. Кэш-supplier,
примитивные стеки, reusable batch/scratch; единственная неизбежная аллокация — MC `Tessellator`/`BufferBuilder` на
draw (устранит будущий батчер). См. [PERFORMANCE.md](PERFORMANCE.md).

**D-14 · `LegacyBackend`/`LegacyText` — исключительно fallback.** Graceful degradation, если шейдер/атлас не
загрузились. Не параллельно поддерживаемый второй UI.

**D-15 · Цвет — упакованный ARGB `int` (`0xAARRGGBB`).** Совместимо с существующим кодом, без боксинга на хотпате;
конвертеры во float для шейдеров.

**D-16 · Процесс: spec-first + subagent-driven.** Спека → approve → план → реализация субагентами (параллель только на
независимых disjoint-файлах) → review → fix → milestone. Бережёт качество и лимит; запрет параллели без утверждённой
спеки. См. [AI_CONTEXT.md](AI_CONTEXT.md).
