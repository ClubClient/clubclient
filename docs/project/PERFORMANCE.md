# PERFORMANCE — принципы и решения

> Принципы производительности нового стека. **Живые цифры/замеры — в `docs/UI-V2-PERF.md`** (не дублируются здесь),
> связанные риски — `docs/UI-V2-RISKS.md` (R2/R10). Здесь — что сделано, что позже, какие компромиссы допустимы.

## Принципы
1. **Alloc-free hot path (свой код).** Никаких объектов на кадр из нашего кода в render-пути. Неизбежные MC-аллокации —
   документируются, не маскируются.
2. **GPU-first.** AA/скругления/glow/градиенты — только в шейдере. CPU-реализаций нет (это потолок старого стека).
3. **Batching-ready.** API не зависит от способа сабмита; батчер добавляется без переписывания компонентов (швы заложены).

## Сделано (Stage 1)
- Кэшированные shader-suppliers (нет лямбды на draw); примитивные `float[]` стеки opacity/clip (нет боксинга);
  reusable `GlyphBatch` (`float[]`) и одиночный scratch `ResolvedGlyph` в Layout; **int-keyed `MsdfMetrics`** (нет
  автобокса `Integer` на резолв глифа); кэш метрик окна для scissor.
- Текст: **1 draw/run** (одна строка → один `BufferBuilder` → один `drawWithGlobalProgram`), 1 texture-bind + 1
  shader-bind на run, 0 atlas-switch внутри run. Фигуры: 1 draw на фигуру.
- Fail-safe без перформанс-цены на success-пути.

## Неизбежно сейчас (acknowledged)
- MC `Tessellator.begin()`/`BufferBuilder`/`.end()` — аллокация на каждый draw (фигура/строка). Это MC-API, не наш код.
- `ShaderProgram.getUniform(String)` — map-lookup на draw (без аллокации).
- `drawWrapped()` пере-переносит текст каждый кадр (`ArrayList`/`StringBuilder`/`split`) — **компоненты должны
  кэшировать wrapped lines** (пересчёт только при смене текста/ширины).

## Позже (Stage 2+)
- **Батчер фигур/текста:** параметры → вершинные атрибуты, накопление quad’ов, flush одним draw на смену
  состояния → draws N→~1–2 и снятие per-draw MC-аллокации. Швы: `// BATCHING SEAM` в `drawShapeQuad`/`GlyphBatch`. API
  `UiRenderer`/`UiText` не меняется.
- **Персистентный VBO** вместо immediate-mode Tessellator.
- Кэшировать ссылки `GlUniform` при init бэкенда (как ванильные шейдеры MC).
- Кэш wrapped lines на уровне компонентов.

## Допустимые компромиссы (Stage 1)
- Immediate-mode MC-аллокация на draw (до батчера) — для UI-масштаба (десятки элементов/кадр) незначительно (R10 → low).
- Per-draw `getUniform` lookup (без аллокации).
- `pushRoundedClip` визуально = прямоугольный scissor (полноценная шейдерная маска — позже; API зафиксирован).
- `line()` только осепараллельный (диагонали аппроксимируются).

## Запрещено
- Любая **per-frame аллокация из своего кода** (Color/List/Radii/лямбды/анонимные классы в render).
- **CPU AA/glow/скругления/градиенты** в `ModernBackend`/`ModernText`.
- Сотни draw-call без заложенного шва к батчингу.
- Литералы цвета/размера в компонентах (только токены, Stage 2+).

> Если для качественного батчинга/перфа потребуется изменить внутреннюю реализацию Stage 1 — делать это ДО появления
> компонентов поверх (пока контракты, а не код, держат систему). Контракты при этом не меняются.
