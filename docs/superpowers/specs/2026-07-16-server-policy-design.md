# Server Policy — Club соблюдает правила сервера

> Статус: **согласовано, не реализовано.** Дата: 2026-07-16.
> Связано: `docs/ITEMSCROLL.md` (модуль, который гейтим первым), `docs/ARCHITECTURE.md` §швы.

## 1. Задача

Аудитория одного сервера играет с Club, а на этом сервере **Item Scroll запрещён правилами**.
Владелец написал администрации: запрет подтвердили и отдельно предупредили, что **попытка обхода —
удар по репутации**. Нужно, чтобы Club не давал игроку запрещённый инструмент именно там,
не ломая его больше нигде.

## 2. Чем это НЕ является

**Это не обход запрета — это его соблюдение.** Обход — спрятать скролл так, чтобы он работал
незаметно для сервера. Здесь противоположное: клиент сам, добровольно и **видимо для игрока**
выключает запрещённую функцию на сервере, где она запрещена. Так делают Lunar и Badlion на Hypixel.
Формулировка в UI и в общении с админами должна оставаться именно такой.

## 3. Решение: один джар, не два

Рассматривались два пути.

| | Один джар + гейт | Отдельный джар без модуля |
|---|---|---|
| Обновление | **Ничего не надо** — джар один | Второй артефакт, вторая страница/файл, второй флоу |
| Промах | Возможен: адрес не из списка → скролл включён | Невозможен физически |
| Если сервер сканирует моды | Не спасает | Спасает |

**Выбран один джар.** Решило то, что запрет держится на **правиле**, а не на сканере: админы
подтвердили словами, про сканирование модов речи не было. Раз нарушение — это поведение, а не
наличие кода, гейта по поведению достаточно, и он снимает всю возню со вторым артефактом.
Требование «обновляется так же, как обычная» при этом выполняется само собой: обновлять нечего,
джар один, релиз-конвейер (`release.yml`, тег → Release → Discord) **не трогаем**.

Если когда-нибудь выяснится, что сервер сканирует список модов, это решение придётся
пересмотреть — гейт тогда бесполезен. Зафиксировано осознанно.

## 4. Ядро

Новый пакет `com.club.policy` — **не** `modules/`: у этого нет ни карточки, ни кейбинда, ни настройки,
это не модуль.

```java
public enum ServerFeature { ITEM_SCROLL }        // строка на каждую запрещаемую функцию

public final class ServerPolicy {
    // Таблица правил. ЗАШИТА В КОД НАМЕРЕННО (см. §7).
    private static final Map<String, Set<ServerFeature>> RULES = Map.of(
        // "example.ru", EnumSet.of(ServerFeature.ITEM_SCROLL)
    );

    /** ЧИСТАЯ функция: что запрещено на этом хосте. Тестируется без бутстрапа игры. */
    static Set<ServerFeature> restrictionsFor(String address) { … }

    /** Можно ли эту функцию там, где игрок стоит прямо сейчас. */
    public static boolean allows(ServerFeature f) { … }
}
```

Разделение на **чистое ядро** (`restrictionsFor`, строки на входе) и **тонкий адаптер**
(`allows`, читает `MinecraftClient`) — чтобы правила проверялись юнит-тестами без запуска клиента,
как это сделано в `ParticleCatalogTest`.

**Добавить сервер или функцию = одна строка в `RULES` / один элемент enum.** Это несущее требование:
полный список адресов владелец получает у администрации отдельно, механизм от него не зависит.

### API, проверенное по `javap` (не по памяти)

- `MinecraftClient.getCurrentServerEntry()` → `net.minecraft.client.network.ServerInfo`
- `ServerInfo.address` — публичное поле `String`
- `MinecraftClient.isInSingleplayer()`, `ServerInfo.isLocal()`, `ServerInfo.isRealm()`

## 5. Совпадение по хосту

Опознание — **по адресу, которым игрок подключился** (то, что лежит в списке серверов).

1. Нормализовать: нижний регистр, отрезать порт, отрезать хвостовую точку.
2. Точное совпадение с ключом таблицы — ловит и голый IP, если он в списке.
3. Совпадение по суффиксу **строго по границе точки**: ключ `example.ru` ловит `play.example.ru`
   и `mc.example.ru`, но **не** `notexample.ru`. Проверка — `host.endsWith("." + key)`, а не
   `host.endsWith(key)`: наивный вариант отдаёт чужой домен, и это сработало бы как ложный запрет
   у постороннего игрока.

Одиночная игра, LAN и `isLocal()` — ограничений нет, спрашивать нечего.

**Неизвестный адрес → разрешено.** Это осознанный fail-open: запрет здесь точечный,
а не глобальный дефолт, и глушить функцию на всех серверах мира из-за правила одного —
неверно. Цена — §6.

## 6. Что гарантирует, а что нет

**Гарантирует:** на сервере из списка Club не отправит ни одного клика Item Scroll.
Закрыты обе точки — и дверь (`active()`), и действие (`act()`), мимо не пройдёт даже харнесс,
который ходит в `act()` напрямую.

**Не гарантирует, что игрок не скроллит вообще.** Он поставит настоящий Item Scroller — и Club
тогда сам отойдёт в сторону (`ItemScrollModule.sibling()` уже так работает). Наше обещание
администрации ровно одно и не больше: **Club не даёт запрещённый инструмент на их сервере.**
Это не граница безопасности и не может ею быть — клиент принадлежит игроку.

**Промах:** зашли адресом, которого нет в таблице → скролл работает. Смягчение — не молчать:
`notice()` показывает состояние строкой, игрок видит, применился запрет или нет. Молчаливый
промах — это и есть тот самый удар по репутации, о котором предупредили админы.

## 7. Почему таблица в коде, а не в конфиге

Конфиг игрок правит блокнотом за десять секунд. Правило в `club_settings.json` — это **обход,
поставляемый нашими руками**, ровно то, от чего предостерегла администрация. Таблица зашита в код.

## 8. Три точки подключения

Паттерн не изобретается: отказ от креативного инвентаря в этом же модуле уже сделан так —
барьер стоит и на двери, и в действии (`ItemScrollHooks.java:138`, комментарий
*«A guard at the door is not a guard on the act»*). Причина та же, что записана в памяти проекта
по итогам Item Scroll: **запрет на двери ≠ запрет в действии** — барьер только в регистрации
однажды обходится.

| Точка | Файл | Роль |
|---|---|---|
| `active()` | `ItemScrollModule.java:51` | **Дверь.** `&& ServerPolicy.allows(ITEM_SCROLL)`. Модуль отходит в сторону, событие достаётся ванили. |
| `act()` | `ItemScrollHooks.java:139` | **Действие.** Ранний `return`. Гарантия для всех вызовов мимо двери. |
| `notice()` | `ItemScrollMenu.java:55` | **Видимость.** Первая по приоритету правда, выше `sibling` и креатива. |

**Дверь обязательна, и вот почему.** Если поставить гейт только в `act()`, то `fire()` вернёт
`true`, `onScroll` вернёт `false` — событие будет **съедено**, и ваниль его не получит. Прокрутка
не сделает ничего вообще. «Половина работает» хуже, чем «выключено» — это правило уже записано
в javadoc `notice()`.

Строка для игрока (английский, как весь UI): `"Off — this server forbids item scrolling"`.

## 9. Чего не делаем (YAGNI)

- **Список с сервера по сети.** Это удалённый рубильник в клиенте игрока — обещание куда большее,
  чем требует задача, плюс сетевой ввод-вывод и отказ в самый неудачный момент.
- **Опция в конфиге** — см. §7.
- **Серверный плагин / хендшейк** — требует участия сервера, которого у нас нет.
- **Сверка по реальному IP сокета** — рассматривалась и отложена: IP серверов меняются, и список
  протухает молча. Возвращаемся к этому, только если промахи окажутся реальными; ядро (§4) это
  переживёт без переписывания.

## 10. Тесты

`ServerPolicyTest` — чистый, без бутстрапа игры (по образцу `ParticleCatalogTest`):

- поддомен ловится ключом домена; чужой домен — нет (`notexample.ru` ≠ `example.ru`);
- порт отрезается; регистр не важен; хвостовая точка не важна;
- голый IP из таблицы ловится точным совпадением;
- неизвестный адрес → пусто (разрешено);
- пустая таблица → разрешено всё (состояние, в котором фича вмерджится до ответа админов).

Ин-гейм проверка — джаром, владельцем. Харнесс здесь не нужен: правило чистое и покрыто юнитами,
а `runClient`-харнесс гонять по кругу запрещено (памятка `harness-run-sparingly`).

## 11. Открытые вопросы (не блокируют реализацию)

1. **Полный список адресов и IP** сервера — владелец запросил у администрации. До ответа
   `RULES` пуст: механизм собран и протестирован, поведение клиента не меняется ни на одном сервере.
2. **Какие ещё функции** запрещены помимо Item Scroll (Fullbright? Freelook?) — владелец уточняет.
   Каждая добавляется одной строкой enum + гейтом в своём модуле по тому же паттерну «дверь + действие».

## 12. Релиз

Не затрагивается. Джар один, `mod_version` и `release.yml` не трогаем. Фича попадёт в ту версию,
в которой будет готова; если это v0.1.4 — секция `CHANGELOG.md` дополняется строкой без обещаний
про «+FPS» и прочих чисел, которых прибор не повторит.
