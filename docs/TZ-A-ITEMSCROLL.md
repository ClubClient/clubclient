## 1. Задача

Дать Club то, что игроки называют «итемскролл» (поведение masa's **Item Scroller**), но:
1. **на уровне качества Club** — не порт, а свой модуль в общем языке мода;
2. **с настраиваемыми жестами** — владелец: *«можно будет самому выбрать какие кнопки отвечают за перемещение
   всего из инвентаря, за перемещение конкретного типа предметов и так далее»*;
3. **без единого кика на сервере.** Club продаётся как «чистый клиент, безопасный там, где банят читы». Мод,
   из-за которого игрока откатывает античит, эту позицию уничтожает.

## 2. Механика (что именно делаем)

### 2.1 Действия (7 штук — это весь набор)

| Действие | Что делает |
|---|---|
| `MOVE_ONE` | переносит **один** предмет из слота под курсором в другой инвентарь |
| `MOVE_STACK` | переносит **стак** |
| `MOVE_MATCHING` | переносит **все стаки того же типа**, что под курсором |
| `MOVE_EVERYTHING` | переносит **всё** из этого инвентаря |
| `DROP_ONE` | выбрасывает один |
| `DROP_STACK` | выбрасывает стак |
| `DRAG_MOVE` | зажать и провести по слотам — переносит каждый, кого задел |

### 2.2 Как это собирается из кликов (проверено по байткоду 1.21.1)

Единственный шов наружу: `mc.interactionManager.clickSlot(syncId, slotId, button, SlotActionType, player)`.
Один вызов = **один пакет**. Батч-пакета не существует.

| Действие | Клики |
|---|---|
| `MOVE_STACK` | `QUICK_MOVE(slot, 0)` |
| `MOVE_MATCHING` | `QUICK_MOVE(s, 0)` по каждому слоту региона, чей стак совпадает |
| `MOVE_EVERYTHING` | `QUICK_MOVE(s, 0)` по каждому непустому слоту региона |
| `MOVE_ONE` | `PICKUP(src,0)` → `PICKUP(dst,1)` → `PICKUP(src,0)` — взять всё, положить один, вернуть остаток. **Курсор обязан быть пуст до и после.** Если в стаке 1 предмет — короткий путь: просто `QUICK_MOVE` |
| `DROP_ONE` / `DROP_STACK` | `THROW(slot, 0)` / `THROW(slot, 1)` — курсор обязан быть пуст |
| `DRAG_MOVE` | `QUICK_MOVE` по каждому слоту, дедуп по id |

Ограничения (тоже проверены): `PICKUP`/`QUICK_MOVE` **не принимают кнопку, кроме 0 и 1** — значит средняя
кнопка мыши не может быть «slot action», она только вход, который мы переводим в клики 0/1. `QUICK_MOVE` по
слоту результата крафта **повторяет крафт**, пока есть ингредиенты — это правильный и дешёвый способ, поэтому
слот результата обслуживается **только** `QUICK_MOVE`. `CLONE` — только креатив. `SWAP`, `PICKUP_ALL`,
`QUICK_CRAFT` — не используем; при совпадении нашего drag-модификатора ванильный quick-craft **отменяем**.

### 2.3 Регионы слотов (без арифметики по индексам — она ломается на модовых экранах)

Слот «на стороне игрока» ⟺ `slot.inventory instanceof PlayerInventory`. Всё остальное — контейнер.
Исключение — `PlayerScreenHandler` (инвентарь выживания), где обе стороны это PlayerInventory: там делим по
`slot.getIndex()` — хотбар 0–8, основной 9–35 (это и есть два региона), **броня 36–39 и офф-хенд 40 в массовых
переносах не участвуют**, сетка крафта 1–4 и результат 0 считаются «контейнерной» стороной.
Пропускать `!slot.isEnabled()` (ткацкий станок, торговец). Никогда не целиться в слот, где
`!slot.canInsert(stack)`.

## 3. ГЛАВНОЕ: темп кликов (иначе игрока откатит)

Ванильный сервер лимита не имеет. **NoCheatPlus** имеет, и по умолчанию: `4 клика/тик`, `15 кликов/сек`,
действие — **`cancel`** (молча). Игрок увидит не кик, а как предметы прыгают назад и появляются призрачные
стаки — и решит, что сломался Club. Независимое подтверждение цифры: Inventory Profiles в своём README сам
советует `intervalBetweenClicksMs = 67` — это ровно 15/с.

**`ClickPacer`** — токен-бакет, качается из `ScreenEvents.afterTick(screen)` (20 Гц, миксин не нужен):

- дефолт: **15 кликов/с**, не больше **3 в тик**;
- очередь **атомарными группами**: три клика `MOVE_ONE` не разрывать между тиками — иначе при закрытии экрана
  между 2-м и 3-м кликом сервер выбросит стак с курсора на землю;
- очередь **умирает** при закрытии/смене экрана и при смене `syncId`;
- пока очередь не пуста — на экране тихий индикатор прогресса (в языке Club, не «прогресс-бар из бутстрапа»);
- **никакого поштучного фолбэка.** У оригинала есть путь, который при невлезающем стаке начинает
  перекладывать по одному предмету — до ~1000 пакетов (их issue #70). Club вместо этого **останавливается** и
  говорит `Target inventory is full`. Отказ дешевле кика.

Настройка `Speed`: `Safe (15/s)` · `Fast (40/s)` · `Instant` — последние два с честной подписью
«may trip server anti-cheat».

## 4. Настройка жестов (то, ради чего всё затевалось)

Модель: **жест = модификаторы + вход**.

```java
record Gesture(int mods, Input input) {}          // mods: битовая маска SHIFT|CTRL|ALT
enum Input { SCROLL_UP, SCROLL_DOWN, LMB, RMB, MMB }
```

Конфиг: `Map<ScrollAction, Gesture>` — по одному жесту на действие.

Требования:
- **Двусмысленных раскладок быть не может.** Назначил жест, занятый другим действием — он у того **отбирается**
  (ровно так же, как в `ModuleBinds.set` / `HoldKeys.steal`), и в UI это **видно**.
- Конфликты с ванилью и другими модами — по образцу `KeyConflicts` (Stage 62): если жест совпадает с тем, что
  делает сама ваниль в инвентаре (Shift+ЛКМ = быстрый перенос!), поповер обязан это **назвать**.
  Особый случай: `Shift+LMB` — это ванильный quick-move. Разрешать его назначать, но предупреждать.
- Дефолты — как в оригинале (мышечная память): scroll = one · Shift+scroll = stack · Ctrl+scroll = matching ·
  Ctrl+Shift+scroll = everything.
- **Направление скролла:** вверх = «наружу из слота», вниз = «внутрь». Плюс галка `Reverse scroll direction`.

UI: карточка **Item Scroll** в категории **Misc** + поповер. Строки жестов — новый ряд-виджет
`GestureRow` (в своём пакете, не в `com.club.ui.component` — тот принадлежит чату C): слева имя действия,
справа «чип» текущего жеста; клик → «Press a gesture…», и мод ловит **следующую комбинацию мышь+модификаторы**.
`Esc` — отмена, `Delete` — снять. Это буквально грамматика захвата бинда из Stage 62, но для мыши.

## 7. Приёмка

**Юнит-тесты** (`src/test/java`) на чистой логике: планировщик слотов (`SlotPlan`) — какие слоты и в каком
порядке кликать для каждого действия; регионы; отбор жеста у другого действия; токен-бакет.

**Харнесс** (в игре, под `// [SEAM:checks]`):
- открыть сундук, положить предметы, выполнить `MOVE_EVERYTHING` → все слоты пусты, курсор пуст;
- `MOVE_ONE` из стака 64 → в источнике 63, в приёмнике 1, **курсор пуст**;
- `MOVE_MATCHING` не трогает предметы других типов;
- броня и офф-хенд не участвуют в `MOVE_EVERYTHING`;
- пейсер: очередь из 60 кликов не выдаёт больше 3 за тик;
- невозможно назначить два действия на один жест (проверка «отбора»).

**Руками:** сундук 54 слота на сервере с NoCheatPlus — ни одного отката. Скриншот поповера с назначенными
жестами — владельцу.

**Коммит:** локальный, после каждого этапа. Тон сообщения — как в существующих коммитах (объясняет причину).
